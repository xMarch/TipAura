# TipAura technical reference

This document is the development and agent-maintenance reference for the current implementation: user-visible behavior contracts, architecture, the encounter YAML schema, threading, audio, settings compatibility, diagnostics, validation and build/release workflows. Read the relevant sections before changing these areas and keep them aligned with the implementation. For the user-facing introduction and quick start, see [README.md](README.md).

ImGui desktop tool that starts encounter countdowns from global hotkeys (Numpad by default, rebindable) and announces them with Windows TTS or sound files, plus two floating windows: timeline bars and center alerts. Requires .NET 10 (or .NET 11, see [Set up and run](#set-up-and-run)), Direct3D 11 (feature level 10.0 or later; WARP is used when no hardware device is available), and Windows 10 19H1 (build 18362) or later on x64. Native AOT additionally requires Visual Studio C++ Build Tools and Windows SDK.

The UI framework (`AppWindow`, `ImGuiRenderer`, `Gpu`, `FrameWaiter`, title bar, window placement, fonts/CJK glyphs, localization, About/licenses), the global keyboard hook thread, `AppLog` and `tools/release.ps1` were adapted from yaaft (MIT, same author). yaaft's capture pipeline, OCR, EXP statistics, SkiaSharp and ONNX/WinML were not taken over; yaaft fixes in those areas do not apply here.

## Source layout

Sources are grouped by domain; all types stay in the global namespace, and the SDK compiles every `.cs` file below the project directory.

| Folder | Domain |
| --- | --- |
| (root) | `Program.cs` entry point, `AppLog`, `BuildInfo` |
| `Encounters/` | Encounter model (`EncounterDefinition.cs`), YAML load/validate/save, pack export and extraction (`EncounterYaml`), zip pack reader and asset keys (`EncounterPack`), countdown state (`TimerEngine`), scheduler thread (`TimerScheduler`) |
| `Audio/` | XAudio2 output (`AudioEngine`), WAV/Media Foundation/Vorbis decoding (`AudioDecoders`), WinRT TTS (`TtsSynthesizer`), prepared-clip cache (`SoundCache`) |
| `Ui/` | Main window, overlay window and its two views, overlay anchors (`OverlayLayout`), window hooks (`WindowHooks.cs`), settings persistence, global hotkeys, icon cache (WIC images and Lucide glyphs), Lucide catalog (`Lucide.cs`), file dialogs, renderer, fonts, localization, About/licenses |
| `SelfTests/` | Agent-only self-tests and smoke tests (each file guarded by `#if TIPAURA_AGENT_SELF_TEST`); `fixtures/` holds small encoded audio files for `--decode-smoke`, the format 1 example and the `demo.zip` pack |
| `data/` | Encounter files shipped next to the exe (`example.yaml`, `sfx/`, `icons/`); users add subfolders and `pack/*.zip` |
| `tools/` | `release.ps1` (see [Versioning and release workflow](#versioning-and-release-workflow)), `lucide-catalog.ps1` (see [Lucide icons](#lucide-icons)) |

## Set up and run

```powershell
dotnet run -c Release
```

`data/**` is copied to the build and publish output.

The target framework is `net10.0-windows10.0.18362.0` by default. The versioned Windows TFM is required: TTS (`Audio/TtsSynthesizer.cs`) uses the WinRT `Windows.Media.SpeechSynthesis` projection, which plain `net10.0-windows` does not reference (it fails with CS0246), and 18362 matches the minimum supported Windows. `-p:TipAuraNet11=true` (on `dotnet run`, `build` and `publish`) builds `net11.0-windows10.0.18362.0` instead; the property only switches the TFM and the zstd backend of [encounter packs](#encounter-packs): SharpCompress is referenced only by the net10 build, and code that differs is under `#if NET11_0_OR_GREATER`. `tools/release.ps1` publishes the default (net10) build. Settings are stored next to the exe in `tipaura.settings.json`, and the log in `tipaura.log` (2 MB, 5 rotated files).

## Threads

| Thread | Owns | Talks to |
| --- | --- | --- |
| Main (UI) | GLFW windows, ImGui contexts, D3D11 device, `IconCache`, the editor's working copy of the encounter | Posts commands to the scheduler; reads `TimerScheduler.Snapshot` and drains its alert queue each frame |
| Global keybinds | `WH_KEYBOARD_LL` hook and `KeybindProcessor` | Enqueues `HotkeyEvent`s and sets the scheduler's wake event; while a key capture is pending, queues the captured key for the UI instead. Bindings are replaced under the hook's lock. Nothing else runs in the callback: Windows silently removes hooks that are slow. |
| Timer scheduler | `TimerEngine` | Calls `AudioEngine.Play` with clips already in `SoundCache`; enqueues `AlertEvent`s for the UI; reads the foreground window for the [hotkey gate](#hotkeys) |
| Thread pool | TTS synthesis and file decoding (`SoundCache`) | Results are read by the scheduler only when complete |
| XAudio2 | Mixing | `CriticalError` only sets a flag; the engine is rebuilt by the next `Play` |

The scheduler sleeps in `WaitForMultipleObjects` on its wake event and a high-resolution waitable timer (`CREATE_WAITABLE_TIMER_HIGH_RESOLUTION`, as in `FrameWaiter`) set to `TimerEngine.NextDeadline()`. Alert timing therefore does not depend on the UI frame rate or on the main window being minimized. Measured alert error is under 3 ms (`--scheduler-smoke`, both JIT and AOT).

The main loop runs at 60 FPS while timers run, alerts are visible, the main window is focused or About is open, otherwise 15 FPS. Overlays render on the same loop.

## Hotkeys

Bindings are local settings (`AppSettings.Hotkeys`, `HotkeyBindings` in `Ui/HotkeyBindings.cs`); encounter files only name the slots 1–9, so there are still nine keys and the YAML does not change. `KeybindProcessor` in `Ui/GlobalKeybinds.cs` matches them:

| Input | Event |
| --- | --- |
| start modifier + key *n* (1–9) | `Start(n)`: start every enabled timer whose `key` includes *n* |
| reset modifier + key *n* | `ResetSlot(n)`: remove every running instance of those timers (a timer bound to several keys is reset by any of them) |
| reset modifier + reset-encounter key | `ResetAll`: clear every running timer |
| anything else, any Win combination | ignored |

Defaults: keys Numpad1–9, reset-encounter key Numpad0, start modifier empty, reset modifier Alt (either side) — the previous fixed bindings.

- Keys: `Keys[0]` is the reset-encounter key, `Keys[1..9]` the slots. A code is the virtual key plus `0x100` for `LLKHF_EXTENDED` (so Numpad Enter ≠ Enter, Insert ≠ keypad 0). Any key except Ctrl/Alt/Shift/Win, Esc and NumLock can be bound; the ten codes must differ.
- Modifiers: `ModifierCombo` sets each of Ctrl, Alt and Shift to `None`, `Left`, `Right` or `Either`, and matches exactly: `None` means neither side is held, `Left`/`Right` exactly that side, `Either` at least one side. The generic `VK_CONTROL`/`VK_MENU`/`VK_SHIFT` count as left; right Ctrl and Alt arrive extended. Two combos overlap when some held state matches both (for example `Ctrl: Either` and `Ctrl: Left`); the start and reset modifiers must not overlap, so a press is never both. Either modifier may be empty, which means the bare key (no Ctrl, Alt or Shift held); since empty overlaps empty, only one of them can be empty at a time. An empty reset modifier therefore makes the bare slot keys reset and the bare reset-encounter key reset the encounter, exactly as an empty start modifier makes the bare slot keys start.
- A key fires once per press; auto-repeat while held is ignored. Keys already held when the hook starts are seeded and must be released first.
- NumLock off: the keypad sends `VK_INSERT, END, DOWN, NEXT, LEFT, CLEAR, RIGHT, HOME, UP, PRIOR` without `LLKHF_EXTENDED`; `HotkeyBindings.Normalize` maps these to the Numpad digit codes, so a Numpad binding works in both NumLock states. The same virtual keys with the extended flag come from the dedicated navigation cluster and are separate keys.
- Settings JSON: `"Hotkeys": { "Keys": [96, …, 105], "StartModifiers": { "Ctrl": "None", "Alt": "None", "Shift": "None" }, "ResetModifiers": { …, "Alt": "Either", … } }`. A missing `Hotkeys` gives the defaults. `HotkeyBindings.Validate` restores the default keys when the list is not ten valid, normalized, distinct codes, an unknown side to its default, and both modifiers to their defaults when they overlap.
- **Settings → Hotkeys** edits the bindings: for each modifier a heading with the current combination (`啟動倒數組合鍵 (LCtrl)`, `無` when empty) and one row per key (Ctrl, Alt, Shift) of Left/Right/Either radio buttons, where clicking the selected radio again clears it to None; below them the overlap message (`組合鍵不可重複`) when a change was refused; one **Bind** button per key and **Restore default hotkeys**. A change that would make the modifiers overlap, or a key already bound to another row, is refused with a message (the key message below the key rows). Bind starts a capture in the global hook (`GlobalKeybinds.BeginCapture`): the next key press that is not a modifier is normalized and queued for the UI and **swallowed** (the hook returns 1 for the press and its release), so it reaches neither ImGui nor the game and fires no hotkey. Esc cancels; so do clicking the button again, leaving the Settings tab and the main window losing focus. Bind is disabled when the hook could not be installed.
- Display: a slot is shown as `Key n (hotkey)` (`按鍵n (LCtrl+Num1)`), the hotkey being the start modifier plus the key's name (`Num0`–`Num9` for the keypad, otherwise `GetKeyNameTextW`). It is used by the Test buttons, the running timers' Key column, the Timers list and the editor's key buttons. The Encounter tab has no hotkey section; the bindings are only shown in Settings → Hotkeys.
- Keys are always passed on to the focused application (`CallNextHookEx`). With NumLock on, Alt+Numpad digits are also Windows Alt-code input, so a focused text box in the game may receive a character.
- **Pause hotkeys while typing** (setting `PauseHotkeysWhileTyping`, default on): each frame the UI sets `TimerScheduler.HotkeysPaused` while the main window is focused and ImGui wants text input (a field is active). The hook still queues events; the scheduler dequeues and drops them (Info log line). The window-focus check matters because ImGui keeps a field active after the game takes focus. The Test buttons are unaffected.
- **Disable hotkeys unless the hooked window is focused** (setting `HotkeysRequireHookFocus`, default off): each frame the UI sets `TimerScheduler.Gate` to a `HotkeyGate` holding the active [window hook](#window-hooks) (null hook when none is selected), or null when the setting is off. The scheduler thread checks `GetForegroundWindow()` when it dequeues a hotkey (not in the hook callback, and not at the UI frame rate): the hotkey is handled when the foreground window belongs to TipAura's own process or matches the hook (`WindowFinder.Matches`), otherwise dropped with an Info log line. With no hook selected, hotkeys work only while TipAura is in the foreground; Settings → Hotkeys says so under the checkbox (and names the hooked window otherwise). The Test buttons are unaffected.
- Hook installation failure is shown in the main window's notice line and in Settings → Hotkeys (where **Bind** is then disabled), and logged. A non-elevated hook does not receive keys while an elevated window is in the foreground (UIPI); run TipAura elevated in that case.

## Encounter YAML

The Encounter tab lists every `.yaml`/`.yml` below `data/` (subfolders included, at most 8 levels, inaccessible folders skipped, nothing under `data/pack/`), sorted by their path relative to `data/`, followed by the `.zip` [packs](#encounter-packs) directly in `data/pack/`; entries are shown by that relative path (`raid/boss.yaml`, `pack/dragon.zip`). `.bak` and `.tmp` files are excluded by their extension. **Refresh** rescans. The listing is a fixed recursive `Directory.EnumerateFiles` (`EncounterYaml.ListDataFiles`); configurable glob patterns were evaluated and not needed, so no globbing package is used. **Open...** loads any other `.yaml`, `.yml` or `.zip`. The selected file is remembered as a name relative to `data/` when it lies inside it, otherwise as an absolute path. Parsing uses YamlDotNet's representation model (`YamlStream`), not its reflection serializer, so it needs no runtime code generation under Native AOT and every issue carries a source line.

### Schema

Root mapping:

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `version` | integer ≥ 1 | detected | File format version (current: 3); see [Format versions and upgrade](#format-versions-and-upgrade). Not an integer ≥ 1 → warning, detected from the content. |
| `id` | text | none | Trimmed. Optional for loose files; a pack's `index.yaml` must set it to the zip's file name (see [Encounter packs](#encounter-packs)). Editable next to the encounter name. |
| `name` | text | file name | Shown in the UI |
| `timers` | list of timer mappings | — | Missing or empty: warning "No timers are defined". Not a list: error. |

Timer mapping:

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `id` | text | — | Required, trimmed, unique in the file. Missing → error, timer skipped. Duplicate → error, later timer skipped. |
| `name` | text | `id` | Bar label; `{name}` in TTS |
| `key` | integer 1–9, or a list of them (`[1, 3]`) | — | Required. Key slots, bound to keys in the local [hotkey settings](#hotkeys) (Numpad1–9 by default); any of them starts the timer, and several timers may share a key. Empty list or invalid item → error, timer skipped. A slot listed twice → warning, kept once. |
| `duration` | number, seconds | — | Required, `0 < duration ≤ 86400`, fractions allowed. Invalid → error, timer skipped. |
| `warn_before` | number ≥ 0 | 0 | Alert this many seconds before the end; 0 alerts at the end. Negative or non-numeric → warning, 0. Larger than `duration` → warning; the alert fires on start. |
| `repeat` | bool | false | When the timer ends it restarts with the same duration, until reset. Accepts true/false/yes/no/on/off; other values → warning, false. |
| `max_instances` | integer 1–20 | 1 | How many copies of this timer may run at once. Invalid → warning, 1. |
| `on_limit` | `replace_oldest` \| `ignore` \| `reset` | `replace_oldest` | What a start does when `max_instances` copies already run: drop the oldest copies to make room and start one; do nothing; or remove every copy and start one. Unknown → warning, default. |
| `sound` | mapping, or list of mappings | none | The sound timeline. Each mapping has `tts`, `sfx` or both (both → two sounds at the same offset, played together), plus an optional `offset`. A mapping without either, or a non-mapping item → warning, ignored. More than 16 sounds → warning, the rest ignored. |
| `sound[].tts` | text | — | Windows TTS. `{name}` → display name, `{sec}` → seconds left when this sound plays (`0` or `0.#`; the warn-before seconds for offset 0), expanded at load so phrases are synthesized ahead of time. |
| `sound[].sfx` | path | — | Relative to the YAML's folder (in a pack: the zip root, and the file must be `sfx/<file>`). `.wav .ogg .mp3 .m4a .aac .wma`; other extension, another pack folder or missing file → warning (that sound is silent). |
| `sound[].offset` | number, seconds | 0 | Relative to the alert point (`duration − warn_before`); negative plays earlier. Sounds with the same offset play simultaneously. `\|offset\| > 86400` or non-numeric → warning, 0. A play time before the start or after the end → warning; it plays at the start or the end. |
| `provider` | text | none | Free text (who supplied the timer, a role…); shown in the Timers list. |
| `note` | text | none | Free-text note, at most 1024 characters (Unicode scalar values); longer → warning, cut off. Shown in the editor and as a tooltip in the Timers list; never on the overlays. |
| `icon` | path or `lucide:<name>` | none | A path is relative to the YAML's folder (in a pack: the zip root, and the file must be `icons/<file>`). `.png .jpg .jpeg .bmp .gif`; unsupported, another pack folder or missing → warning. Scaled to at most 128 px. `lucide:<name>` is a built-in icon (see [Lucide icons](#lucide-icons)); prefix and name match case-insensitively and are saved in lower case; an unknown name → warning, no icon, the value is kept. |
| `message` | text | display name | Center alert text |
| `color` | `#RRGGBB` or `#RRGGBBAA` | blue bar, gold alert text | Bar color and alert text color. Invalid → warning, default. |

Unknown fields at any level → warning, ignored. A non-numeric value for a required number is an error; for an optional number it is a warning and the default is used. A YAML syntax error or a root that is not a mapping fails the whole file. Any other error only skips its timer, so the rest of the file still loads. The Encounter tab lists every issue as `L<line>: message`.

### Format versions and upgrade

`EncounterYaml.FormatVersion` is the current format (4). `EncounterLoadResult` carries `Version` (the format the file was read as), `Tagged` (whether it declared `version`) and `NeedsUpgrade` (`!Tagged || Version < FormatVersion`); a file that fails to load reports the current format and needs no upgrade.

| Version | Since | Difference from the previous version |
| --- | --- | --- |
| 1 | a80e300 | — (`key` one integer, `sound` one mapping; a sound with both `tts` and `sfx` → warning, only the `sfx` plays) |
| 2 | ff44fc2 | `key` lists, `sound` lists, `sound[].offset`, `provider`, `note`; a sound with both `tts` and `sfx` plays both. `version` is written from this version on. |
| 3 | encounter packs | Root `id`. Nothing else changes, so `V2ToV3` is empty; format 2 files still show the upgrade notice. |
| 4 | Lucide icons | `icon: lucide:<name>` (see [Lucide icons](#lucide-icons)). `V3ToV4` is empty: in format 3 such a value was a file path that cannot exist on Windows, so it is read as the icon; format 3 files still show the upgrade notice. |

A file without `version` is format 4 when any timer's `icon` starts with `lucide:`, format 3 when the root has `id`, format 2 when any timer uses format 2 syntax (`key` or `sound` is a sequence, a `sound` mapping has `offset`, or the timer has `provider` or `note`), otherwise format 1. Files saved by TipAura before `version` was written are format 2 but untagged; one that only differs from format 1 by a `tts` + `sfx` sound is read as format 1, as it played under format 1. A `version` above the current one → warning ("newer than this TipAura supports"); the file is read with the current rules and no upgrade is offered.

Older formats are migrated on YamlDotNet's node tree before parsing (`EncounterYaml.Migrations[n − 1]` turns a format *n* tree into *n* + 1), so line numbers stay correct and the parser only knows the current format. `V1ToV2` removes `tts` from a sound mapping that also has `sfx` and repeats format 1's warning; `V2ToV3` and `V3ToV4` change nothing. To add format 5: bump `FormatVersion`, append a `V4ToV5` step, extend `DetectVersion` only if untagged files can still occur, and add a row here.

While the loaded file needs an upgrade, the Encounter tab shows "This file uses the older format version N" (or "does not declare its format version" for untagged format 2) with an **Upgrade** button. Upgrade is **Save YAML** on the same path: any save that overwrites the loaded file while it needs an upgrade goes through `EncounterYaml.Upgrade`, which first copies the file to `<file>.v<N>.bak` (`<file>.v<N>-2.bak`, `-3`… when taken; never overwritten) and then saves. The backup keeps the original comments; the toast names it. A backup failure is a save error and nothing is written. **Save as...** to another path writes the current format without a backup. `.bak` files are not listed in the Encounter combo.

### Saving

**Save YAML** and **Save as...** write the editor's working copy through `EncounterYaml.Serialize`: `version` first, fixed key order (`version`, then `id` when set, `name`, `timers`), every scalar field written explicitly (`name` is written as the display name), `sound`/`icon`/`message`/`color`/`provider`/`note` only when set. A single key is written as a number and several as a flow list (`key: [1, 3]`). A single sound with offset 0 keeps the short mapping form (`sound: {tts: …}`); otherwise `sound` is a list with `offset` written when non-zero. Multi-line notes are written as literal blocks. Strings that YAML would read as another type (numbers, booleans, null, leading indicators, `": "`, `" #"`, surrounding spaces) are double-quoted; CJK text stays readable. Comments and formatting of the original file are not preserved. Writes go to `<file>.tmp` first and are then moved over the target. **Save as...** into another folder rewrites relative `sfx` and `icon` paths so they still point to the same files (`lucide:` icons are kept as they are). For a pack the button is **Save pack**, which rewrites the zip, and **Save as...** is replaced by **Extract to data** (see [Encounter packs](#encounter-packs)).

The Timers tab list can be shown in file order, by key (lowest bound key, then duration) or by time (duration, then lowest key); ties keep the file order. Sorting only changes the display, never the file; the choice is the `TimerSort` setting. The up/down buttons next to the sort box move the selected timer in the file order (an edit like any other) and are enabled only in file order. Each list entry has a checkbox and shows its first key, name and provider; further keys go on their own lines, at most three lines in total, with `+N` for the rest. Hovering a timer shows its note. Unchecking a timer disables it for the session (`MainWindow._disabledTimers`, sent to `TimerScheduler.SetDisabled`): its keys and the Test buttons no longer start it, running copies are removed and the entry is dimmed. This is not an edit: the YAML, the undo history and the dirty state do not change, nothing is saved, and loading a file or New encounter enables every timer again. Renaming a disabled timer's id keeps it disabled.

Edits in the Timers tab replace the working copy immediately and mark it dirty (`*` on the tab). Once no widget is active, the working copy is pushed to the scheduler, which clears running timers, and its sounds are prepared. Loading another file while dirty asks for confirmation.

Editor history (`EditHistory<T>`, `MainWindow.Edit`): every change goes through `Edit`, which pushes the previous `(encounter, selected timer, revision)` onto a 50-step undo stack; a new edit clears redo. Edits while the same widget stays active (ImGui's internal active ID via the cimgui export `igGetActiveID`) are one step, so typing in a field or dragging a slider undoes at once; Tab to another field, deactivation, a save, undo/redo and discard start a new step. Each edit gets a new revision and the copy is dirty while its revision differs from the saved one, so undoing back to the saved state clears `*`. Loading a file (combo, Reload, Open...) and New encounter clear the history; Save and Save as... keep it. **Ctrl+Z** undoes, **Ctrl+Y**/**Ctrl+Shift+Z** redo, only while no text field is active (a field keeps ImGui's own per-field undo) and no popup is open. **Ctrl+S** saves on every tab, also while typing, or opens Save as... for an unsaved encounter. **Discard changes** (right end of the save row, enabled when dirty and saved to a file) reloads the file without confirmation as one undoable edit and marks the result clean; if the file no longer parses, the issues are shown and nothing changes.

A successful save shows a toast in the main window's bottom-right corner for 5 s (fading over the last 0.5 s), drawn as a separate input-less ImGui window above the full-window `###Main` window (which has `NoBringToFrontOnFocus`). Save errors still go to the notice line; a later successful save clears that notice.

The note box grows with its text: `clamp(lines + 1, 5, 12)` lines, so the last line is always empty, then it scrolls. The character count is inset in its bottom-right corner on `FrameBg` at half alpha, drawn as an input-less child window submitted after the box (the box is itself a child window, which would cover the parent's draw list).

### Encounter packs

A pack is a `.zip` holding one encounter and its assets (`EncounterPack`, `EncounterYaml.LoadPack`):

- Location and id: packs are listed from `data/pack/*.zip`; **Open...** also accepts a zip elsewhere. The zip must contain `index.yaml` at its root, and that file must declare `id` equal to the zip's file name without `.zip` (case-insensitive). A missing `index.yaml`, a missing `id` or a different one is an error and the pack does not load. `index.yaml` is read as UTF-8 (a BOM selects another encoding), as loose files are.
- Asset sandbox: `sfx` and `icon` paths are entry names relative to the zip root. `\` counts as `/`, `.` and inner `..` are folded, and names match case-insensitively. An absolute path, a drive (`:`) or a path that climbs above the root → warning "must be a path inside the pack" and the asset is not used; a sound outside `sfx/` or an icon outside `icons/` (with a supported extension) → warning "must be directly in the pack's sfx/ folder"; a missing entry → warning "is not in the pack". Nothing outside the zip is ever read for a pack, not even next to it.
- Layout (`EncounterPack.AssetFolder`): besides `index.yaml`, a pack may only hold sounds directly in `sfx/` (`sfx/<file>` with a sound extension) and images directly in `icons/` (`icons/<file>` with an image extension); folder names match case-insensitively. Any other entry (another folder, a subfolder, a file at the root, a sound in `icons/`, a readme) fails the whole pack with "is not allowed". Flat folders give every asset a unique file name, which extraction relies on.
- Zip rules, checked when the pack is opened (any failure is an error for the whole pack): entry methods Zstandard (93), Deflate (8) or stored (0); no encryption; entry names must already be normalized (`a/b.ogg`; no `\`, `..`, `.`, empty segments, leading `/` or `:`), follow the layout above and be unique ignoring case; at most 4096 entries and 64 MB uncompressed per entry; split archives are rejected. Directory entries are skipped. On read, the decompressed length must equal the declared size (truncated or longer → error). CRC-32 is not checked.
- .NET 11 (`#if NET11_0_OR_GREATER`): `System.IO.Compression.ZipArchive` cannot read or write method 93 (`ZipCompressionMethod` has only Stored, Deflate and Deflate64) and does not expose an entry's data offset, so `EncounterPack` reads the end record (Zip64 included), the central directory and each local header itself and decompresses with `ZstandardStream`/`DeflateStream`. It also writes packs itself (`EncounterPack.Write`): local header and `ZstandardStream` data per entry, central directory, end record; version needed 6.3, UTF-8 flag, CRC-32 from a table, no Zip64 (a pack over 4 GB is refused). Names need the UTF-8 flag (bit 11) unless they are ASCII. .NET 10: SharpCompress (`ZipArchive.OpenArchive`, `OpenEntryStream`; `ZipWriter` with `CompressionType.ZStandard` and `ArchiveEncoding.Default = UTF8`, without which it writes UTF-8 names but does not set bit 11) with the same checks applied to its entries.
- Asset keys: `Encounter.Resolve` returns `<full zip path>|<entry>` for a pack (`|` cannot occur in a Windows path), or the source file's full path for a file added in the editor (`Encounter.PackFiles`). `EncounterPack.ReadAsset` reads either a key or a loose path; opened packs are kept by path, so keys can be read on the thread pool. Every read opens the zip again, and loading or reloading a pack opens it anew, so a replaced zip is picked up. `AudioDecoders.Decode` decodes entries from memory: WAV parser, NVorbis on a `MemoryStream`, and Media Foundation through `MFByteStream` + `MFCreateSourceReaderFromByteStream` (the source resolver sniffs MP3/M4A without a content type). `IconCache` decodes them through a WIC stream.
- Editing: the editor works on the working copy as for loose files. **Save pack** (Ctrl+S, enabled when dirty) is **Export pack** to the loaded zip itself: it rewrites the zip in the current format with only the files the timers use, then reloads it, which clears the undo history and the session's disabled timers. **Discard changes** reloads the zip. There is no upgrade notice or `.bak` for a pack.
- Pack files (`MainWindow.DrawPackFiles`): **Browse...** for a sound or icon opens a modal listing the pack's `sfx/` or `icons/` files (`Encounter.PackAssets`) with a **Preview** button per sound or a thumbnail per icon; clicking a file sets the field (one edit). **Add file...** in it opens a file dialog (starting in `data/sfx` or `data/icons`) and adds the file with `EncounterYaml.AddPackFile`: it becomes `sfx/<file name>` or `icons/<file name>` in `Encounter.PackFiles` (entry → source path) and is selected, as one undoable edit. When the pack (or an added file) already holds the same bytes under that name, the existing entry is reused; other bytes get `-2`, `-3`…. A wrong extension or a file over 64 MB is refused with a notice. Added files are read from their source until the pack is saved and are marked "added, not saved yet". **Pack files...** next to **Export pack...** opens the same modal without picking, with Sounds and Icons tabs. Files no timer uses are dimmed, with a tooltip that saving removes them.
- Extract to data (`EncounterYaml.PlanExtraction`/`ApplyExtraction`, **Extract to data** in place of **Save as...**, the working copy with unsaved edits): every sound and icon a timer uses is written to `data/sfx/<pack>_<file>` or `data/icons/<pack>_<file>`, and the encounter, referring to those paths and keeping its `id`, to `data/<pack>.yaml`, `<pack>` being the zip's file name. `lucide:` icons write no file; an asset missing from the pack keeps its path and is not extracted. An existing file with the same bytes is left alone. Existing files with other contents are asked about one at a time in a modal (`data/<path> already exists with different contents`, with a counter) offering **Overwrite**, **Keep existing**, **Overwrite all**, **Keep all** and **Cancel extraction**; cancelling writes nothing. Files are written through a temporary file. When the YAML in `data/` ends up being the extracted one (written, or already identical), it is loaded; when the existing YAML was kept, the pack stays open. The toast reports the files written and kept.
- Export pack (`EncounterYaml.WritePack`, **Export pack...** next to **Save as...**/**Extract to data**, for loose files and packs alike): enabled once the encounter has an `id`. The dialog proposes `data/pack/<id>.zip`; the chosen file must be named `<id>.zip` and the id must be a valid file name, otherwise an error. Every referenced `sfx` and `icon` is checked and read first (a `lucide:` icon is not a file: it stays in `index.yaml` and adds no entry): each sound goes to `sfx/<file name>` and each icon to `icons/<file name>`, numbered `-2`, `-3`… when that name already holds other bytes; the same source file is stored once. A missing asset, an extension that does not fit (an image as a sound or the reverse), or a file over 64 MB fails the export before anything is written (an existing zip stays as it was). Then `index.yaml` (serialized with the new paths, current format) and the assets are written Zstandard-compressed to `<id>.zip.tmp` and moved over the target, and the result is opened again as a check. Files of the source pack (and added files) that no timer uses are not written; the toast reports their number ("N unused file(s) removed"). The open document is not changed (it keeps its paths and file); writing over the loaded pack reloads it from the new zip, as **Save pack** does. The overwrite prompt is the file dialog's.

## Countdown engine

`TimerEngine` (pure, not thread-safe, time in caller-supplied ticks) holds running instances. Each has `Start`, `End = Start + duration`, `AlertAt = End − min(warn_before, duration)`, an `Alerted` flag, and the absolute play time of each sound (`AlertAt + offset`, clamped to `[Start, End]`), sorted, with the index of the next one.

- `Start(slot, now)` applies each matching timer's limit rule (oldest = earliest start, then lowest id), adds an instance and returns cues already due (`warn_before ≥ duration`, or sounds clamped to the start).
- `Advance(now)` emits one `TimerCue` for the alert (`Sound = −1`) once `AlertAt` has passed and one per sound whose time has passed, then removes instances whose `End` has passed (sounds clamped to the end still play). A repeating instance reschedules from its previous `End`, not from `now`, so cycles do not drift. After a stall it skips whole missed cycles and emits the alert and each sound at most once, for the cycle containing `now`.
- `NextDeadline()` is the earliest pending alert, sound or end.
- `ResetSlot`, `ResetInstance` and `ResetAll` remove instances without alerts. `Load` replaces the encounter and clears everything except the disabled set.
- `SetDisabled(ids)` holds the timer ids disabled for the session: `Start` skips them and the call removes their running instances. `Load` keeps the set, so applying an edited working copy does not re-enable timers.
- `Snapshot()` returns views sorted by end time; each view carries the absolute `EndTicks`, so the UI computes the remaining time for its own frame.

An alert cue makes the scheduler enqueue an `AlertEvent` (center alert); a sound cue plays that sound's clip when it is ready. Each sound is its own XAudio2 voice, so sounds at the same time overlap and each counts toward **Simultaneous sounds**. A clip that is still being prepared or that failed is skipped (throttled warning in the log).

## Audio

- **TTS**: `Windows.Media.SpeechSynthesis.SpeechSynthesizer` through the CsWinRT projection of the TFM (works under Native AOT; verified by `--tts-smoke` on the AOT build). Output is a RIFF/WAVE stream (OneCore voices: 16 kHz mono PCM). The voice is selected by id from settings (null = system default); speaking rate 0.5–3.0.
- **Decoding** (`AudioDecoders`): WAV PCM 8/16/24/32-bit and float32 (including `WAVE_FORMAT_EXTENSIBLE`) by an in-process parser; other WAV encodings, MP3, AAC/M4A and WMA through Media Foundation `IMFSourceReader` converted to float; Ogg Vorbis through NVorbis. Ogg Opus is rejected. Windows N editions without the Media Feature Pack cannot decode MP3/AAC. Clips are limited to 120 s and stored as interleaved float on the pinned object heap.
- **Cache** (`SoundCache`): keyed by `sfx + full path` (a pack asset key for packs) or `tts + voice + rate + expanded text`, so identical sounds are prepared once. Loading a file or picking a new sound/icon file clears the cache; changing the voice or rate changes the keys. Every sound of every timer is prepared separately. The Encounter tab shows ready/preparing/failed counts per sound and the editor shows each sound's error. In the editor, each sound is a two-line block (type, offset, preview and remove; then the text or file) marked by a bar on its left, and its preview button plays that sound; **Preview all** plays the timer's sounds with their relative spacing.
- **Output** (`AudioEngine`): XAudio2 with a mastering voice (category GameEffects) carrying the master volume. Each play creates a float source voice for the clip's format and submits the pinned samples without copying. **Max sound length** (`MaxSoundSeconds`, default 10 s, 1–120) sets `AudioEngine.MaxPlaySeconds`: a longer clip is submitted with `AudioBuffer.PlayLength` set to that many frames, so XAudio2 ends the voice there (an abrupt cut, no fade) and it is reaped as a finished voice. It applies to every play (sound files, TTS, Preview, Preview all) from the next play on; clips are not re-decoded. **Simultaneous sounds** (default 10, 1–32) caps live voices; reaching it stops and destroys the oldest voice first. Finished voices are reaped on the next play or query. A critical error (device removed) rebuilds the engine on the next play.

## Floating windows

Both are `OverlayWindow`s: layered (`UpdateLayeredWindow`, per-pixel alpha), `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`, not in the taskbar, shown without activation so the game keeps focus. **Locked** sets `WS_EX_TRANSPARENT` (click-through). Unlocked, the window draws an outline, the whole window drags and 9 px edges resize it; the new position and size are saved when the mouse is released. Each has its own ImGui context and font size; textures (icons) are shared through the single D3D11 device.

| Window | Default placement | Contents |
| --- | --- | --- |
| Timeline (`OverlayViews.DrawTimeline`) | 320×260, anchor top right, offset (−16, 16); text 18 px; background 35% | Up to **Bars shown** (default 8) bars, soonest end first: a square icon column on the left (always reserved, so bars line up whether or not a timer has an icon), then the bar: a fill that empties as time runs out, name, remaining time (`0.0` below 10 s, whole seconds below 60 s, then `m:ss`/`h:mm:ss`). The fill uses `color` at 90% alpha and turns pulsing orange once the alert has fired. With **Monochrome colors** every bar uses the colors of the current theme instead (see below). |
| Center alerts (`OverlayViews.DrawAlerts`) | 900×200, anchor top center, offset (0, 80); text 44 px; no background | Newest alert on top, icon + `message`, outlined text in `color`, 150 ms pop-in, held for **Alert duration** (1–10 s, default 3) and faded over the last 0.5 s. At most 6 alerts are kept. |

Monochrome timeline (`TimelineMonochrome`, off by default): the timeline ignores each timer's YAML `color` and draws with a `TimelineColors` set — `Text`, `Shadow` (text shadow), `Fill` (bar), `Track` (the empty part behind the fill) and `Flash` (the pulsing color after the alert, replacing orange) — each `#RRGGBB` or `#RRGGBBAA`, used with its own alpha. There is one set per theme (`MonochromeDark`, `MonochromeLight`), not shared; `AppSettings.MonochromeColors` picks the current theme's, so switching the theme switches the colors. Lucide icons take the fill color, opaque; image icons are unchanged. Center alerts always keep the YAML color. Without monochrome, the track, text and shadow keep their fixed colors (`#0D0D0FBF`, white, `#000000C0`).

**Settings → Floating windows** has a sub-heading per window (**Timeline bars**, **Center alerts**), each starting with **Enabled**, **Locked (no preview or editing)** (click-through and no placeholder), **Topmost** and **Reset position**, then anchor, text size and background. The timeline section adds Bars shown, Discord capture and **Monochrome colors**; when that is on, a row of color swatches edits the current theme's set, with **Restore default colors** for that theme.

Positions follow yaaft's floating-window anchors (`OverlayLayout`, ported from yaaft `OverlayData`). The reference rectangle is the client area of the active [window hook](#window-hooks)'s window, or the primary work area while no hook is selected. `Anchor` (0–8, row-major 3×3) aligns the matching point of the overlay with that of the reference: origin = `Left + floor((W − w) · column / 2)`, `Top + floor((H − h) · row / 2)`, and the stored X/Y are the offset from that origin (null = the default offset above). The result is clamped into the work area the overlay overlaps most (or, when it overlaps none, the one the reference overlaps most). The overlay therefore follows the hooked window when it moves or resizes; the client area is read every frame. When a drag or resize ends, `OverlayWindow.Moved` reports the screen position and `RememberPosition` stores it as the offset from the current anchor (with the new size). The 3×3 **Anchor** buttons in **Settings → Floating windows** change the anchor and recompute the offset so the overlay stays in place; they are disabled while the hooked window is missing. **Reset position** restores the default anchor, offset and size. While a hook is selected but its window is closed or minimized, both overlays are hidden with `ShowWindow(SW_HIDE)` (not disposed, so their font atlases survive). Overlays render whenever enabled, independent of the main window being minimized.

## Window hooks

A window hook (`WindowHook` in `Ui/WindowHooks.cs`) binds the overlays to a game window and remembers an encounter file. Hooks are stored separately from the other settings in `tipaura.windows.json` next to the exe (`WindowHookStore`, System.Text.Json source generation, written through a temporary file like `tipaura.settings.json`):

```json
{
  "Hooks": [
    { "Name": "Artale", "Match": "ProcessName", "Pattern": "msw.exe", "EncounterPath": "example.yaml" }
  ],
  "Active": 0
}
```

- `Match`: `ProcessName` compares the executable name case-insensitively, with `.exe` optional on both sides (`QueryFullProcessImageNameW` with `PROCESS_QUERY_LIMITED_INFORMATION`, so no `Process` objects); `Title` matches any case-insensitive part of the window title. `EncounterPath` uses the same form as `AppSettings.EncounterPath` (a name inside `./data`, otherwise absolute). `Active` is the index of the selected hook, −1 for none.
- `WindowHookSettings.Validate` (load and save) trims patterns, drops hooks with an empty pattern (an unsaved row being typed stays in memory), names unnamed hooks after their pattern, keeps at most 64 hooks and remaps or clears `Active`. An unreadable file is reported on the main window and treated as no hooks.
- **Settings → Window hooks** edits the list: name, match kind, pattern, encounter file (from the data file list), remove; **Add hook**, and **Add from running window...**, which lists visible, titled top-level windows of other processes (`EnumWindows`) when opened and adds a process-name hook.
- **Encounter → Window hook** selects the active hook. Selecting goes through the unsaved-changes prompt, then loads the hook's file when it exists and differs from the current one (a missing file only shows a notice); a hook without a file remembers the current one. While a hook is active, every load or save-as stores the file in the hook. Switching is manual only: the foreground window never changes the active hook. At startup the active hook's file, when present, takes precedence over `EncounterPath`.
- Lookup (`MainWindow.UpdateOverlayBounds`): once a second the cached window is checked with `WindowFinder.Matches` and, when it no longer matches or is minimized, `WindowFinder.Find` searches again, preferring the foreground window, then the first visible non-minimized match in Z order. The client rectangle (`GetClientRect` + `ClientToScreen`, physical pixels under per-monitor DPI awareness v2) is read every frame. With no window, overlays are hidden and the Discord capture feed sends black frames as for a hidden timeline.

### Discord capture

Layered overlays have no swap chain, so an `IDXGISwapChain::Present` hook such as Discord's stream capture cannot see them. With **Discord capture (timeline)** (`DiscordCapture`, global, off by default) the user streams the *main window* in Discord, and the hook receives the timeline instead of the main UI.

How the hook chooses (from `%APPDATA%\discord\logs\discord_hook.log` and the strings of `DiscordHook64.dll`): it inline-hooks `Present`, `Present1`, `ResizeBuffers(1)` and `Release` of DXGI swap chains, keeps the swap chain it starts capturing from (`Capturing using shared textures`), and only moves on when that one is released (`Resetting DXGI state due to swapchain release`) or stops presenting (`Swap timeout`). It does not require the swap chain to belong to the selected top-level window: VLC's D3D11 output presents on a child video window, and Discord shows the whole VLC window (window capture) for a few seconds, then only the video once the hook takes over, because the Qt UI uses no swap chain. A first version that showed TipAura's UI through a DirectComposition *swap chain* failed: the UI presented first every frame and the hook kept it.

So in capture mode **the timeline feed is the only swap chain that presents in the process**:

- `AppWindow.Composited` (main window and the About window, through `AuxiliaryWindows.Composited`) draws each frame into an offscreen texture and shows it through `CompositionPresenter`: a DirectComposition target on the window (`topmost`), a visual and an `IDCompositionSurface` (`BeginDraw`, copy at the returned offset, `EndDraw`, `Commit`). No swap chain is involved, and the visual covers the HWND content, so the screen does not change.
- After the overlays render, `MainWindow.PresentDiscordCapture` calls `AppWindow.PresentCapture`: the main window's HWND swap chain is resized to the timeline frame, the timeline's layered render target (`OverlayWindow.FrameTexture`, premultiplied BGRA) is copied into it, and it is presented. It is the same swap chain that presents the UI while capture is off, so a stream already running keeps its hook on it. Transparent pixels come out black. A hidden timeline sends black frames at the saved timeline size. The feed keeps presenting while the main window is minimized (Present returns occluded).
- Layered overlays never present a swap chain; the center alerts are never captured.
- Turning it off disposes the DirectComposition objects; the next frame resizes the HWND swap chain back and draws the UI into it. Any failure logs under `Capture`, shows a notice and turns the setting off. If the About window cannot switch, it logs and keeps presenting its own swap chain.

Discord may still record the visible main UI through window capture before the hook takes over, or when it does not hook TipAura at all; adding TipAura under Discord's registered games makes it treat TipAura as a game. To diagnose, look for `Starting graphics hook` and `Capturing using shared textures` for TipAura's PID in `discord_hook.log`.

## Fonts and glyphs

UI fonts are Consolas plus Microsoft JhengHei merged with `CjkGlyphs.Ranges`: Latin, punctuation, Big5 level 1, every localized string, and (via `CjkGlyphs.SetExtraText`) the encounter's name, timer names, messages, providers and notes, so user text outside Big5 level 1 still renders. Setting new text bumps `CjkGlyphs.Version`; renderers whose atlas is older rebuild it between frames (`ImGuiRenderer.GlyphsStale`). The alert window uses a large font, so it builds its atlas only from the encounter text, its placeholder strings and digits (`CjkGlyphs.RangesFor`), not from Big5 level 1. Text from files, paths and exceptions is drawn with `TextUnformatted`/draw-list calls, never as an ImGui format string.

## Lucide icons

`Ui/Lucide.cs` holds two things. The hand-written `const` codepoints at the top are UI glyphs: only `Lucide.Atlas` is baked into every renderer's font atlas (`IconFont`), and `--ui-smoke` checks it is complete. Below `// BEGIN GENERATED` is the timer icon catalog: `Lucide.Category` (flags), `Lucide.Categories` (lucide.dev titles, also the localization keys of the picker's category combo) and `Lucide.Icons`, every icon of the lucide.dev categories Accessibility, Animals, Buildings, Emoji, Food & beverage, Nature, Navigation & Places, People, Science, Seasons, Shapes, Sustainability, Tools, Transportation, Travel and Weather (605 icons in 1.51.0), sorted ordinally by name for `Lucide.Find`'s binary search. Do not edit the generated region by hand: `tools/lucide-catalog.ps1 -Repo <lucide-icons/lucide source at the font's tag> -Static <lucide-static package>` rewrites it from the repository's `icons/*.json` (`categories`) and `categories/*.json` (titles) and the package's `font/codepoints.json`; its help shows the downloads. It refuses to run unless `assets/fonts/lucide-<package version>.ttf` exists, so the catalog always matches the embedded font. When upgrading the font, rename the TTF, regenerate, check the UI constants against the new `codepoints.json`, and update the version in `Lucide.cs`, `ThirdPartyNotices.cs` and the script's example. To add a category, pass `-Categories` with the full list (at most 16; `Category` is a `ushort`) and add its title to `Localization`.

- Values: `lucide:<name>` with the lucide.dev name (kebab case). `Lucide.IsIcon` (prefix only) decides that a value is never a file path: `Encounter.Resolve` returns it trimmed, and the YAML file check, **Save as...** rebasing, pack extraction and **Export pack** skip it. The parser normalizes a known name to `Lucide.Icon.Value`. It was added in format 4 (see [Format versions and upgrade](#format-versions-and-upgrade)); a TipAura that only knows format 3 warns that the version is newer and reports the value as an unsupported file type, without an icon.
- Rasterizing (`IconCache.RasterizeGlyph`): the glyph alone is baked at 128 px into a throwaway `ImFontAtlas` (`OversampleH/V = 1`, so atlas pixels map 1:1; ImGui's default horizontal oversampling doubles the bitmap width), from the same native copy of the TTF as the UI atlases, and copied into a 128 × 128 coverage square: the line box vertically (the font's ascent is the full em), centered on the advance horizontally, so every icon keeps Lucide's 24-unit grid and padding (`square` lands at 11…116). The metrics are read from the native `ImFontGlyph` (a `uint` of bit fields, then `AdvanceX, X0, Y0, X1, Y1, U0, V0, U1, V1`) because ImGui.NET's `ImFontGlyphPtr` maps them at wrong offsets for this cimgui. The TTF's glyph boxes start at the origin, so the baked bitmap is larger than the ink; only the ink matters after the copy.
- Textures: `R8_UNorm` and `AlphaOnly` (the alpha pixel shader draws them in the vertex color), with a box-filtered mip chain (`GpuTexture.UploadMipmapped`) so thin strokes stay smooth at bar height. `IconCache` keeps glyph textures by codepoint for its lifetime; `Clear` (for edited image files) does not drop them.
- Drawing (`OverlayViews.DrawIcon`): image icons are drawn as before. A glyph takes `OverlayViews.IconTint` (the timer's `color`, opaque, or the default bar color) on the timeline and the alert text color in alerts, over a black shadow offset by 1/24 of its size, and fades with the alert. The editor preview uses `IconTint` too.
- Picker: **Lucide...** next to the Icon field opens a popup with a name search (spaces count as `-`), a category combo and a 10-column grid of `ImageButton`s in the text color, with the current icon highlighted and the name as tooltip. `ImGuiListClipper` draws only the visible rows, so only their glyphs are rasterized. Picking writes `lucide:<name>` into the timer and closes the popup. It works for packs as well; there it adds no file.

## Settings

`tipaura.settings.json` (System.Text.Json source generation; window hooks are in their own file, see [Window hooks](#window-hooks)). Missing properties keep their defaults (the properties of `AppSettings` and `OverlayPlacement` must use `set`, not `init`: source generation passes `default(T)` for init-only properties missing from the file; inside a partial `Alerts` object, missing fields take `OverlayPlacement`'s own defaults rather than `DefaultAlerts`); `AppSettings.Validate` clamps every value on load and save: volume 0–1 (default 0.8), simultaneous sounds 1–32 (10), TTS rate 0.5–3, font 10–32 px (16), theme 0/1, language `en` or null (Traditional Chinese), overlay sizes ≥ 160×60, overlay text 10–96 px, alert duration 1–10 s, bars 1–30, `MaxSoundSeconds` 1–120 (default 10), `TimelineMonochrome` (bool, default false), `MonochromeDark`/`MonochromeLight` (`{ "Text": "#FFFFFF", "Shadow": "#000000C0", "Fill": "#458CD9E6", "Track": "#0D0D0FBF", "Flash": "#E66B2E" }` for dark; light defaults `#1A1A1A`, `#FFFFFFC0`, `#7FB0E8E6`, `#E6E6EABF`, `#E66B2E`; a missing set takes the theme's defaults and an invalid color that field's default), timer list sort 0–2 (file order, key, time), `PauseHotkeysWhileTyping` (bool, default true), `HotkeysRequireHookFocus` (bool, default false), `DiscordCapture` (bool, default false), overlay `Anchor` 0–8 and X/Y offsets ±100000. Overlay anchors were added after the first settings format: a file without `Anchor` loads it as −1, and when that placement also has X and Y (then absolute screen coordinates) the `MainWindow` constructor converts it with `OverlayLayout.MigrateLegacy` to anchor 0 with the offset from the primary work area's top-left, so the overlay stays where it was while no hook is selected; without X/Y it takes the default anchor. The font-size and overlay text-size sliders keep the dragged value in a draft and commit it when released, so the font atlas is rebuilt once. The main window position is restored like yaaft's (`WindowPlacement`). Saving is debounced to once per second and skipped while a widget or window drag is active; the final state is saved on exit. A settings file that cannot be read is reported on the main window and defaults are used.

## Localization

English strings are keys; `Localization.T`/`F` return the Traditional Chinese text unless the language setting is `en`. Language changes need a restart. When adding UI text, add the key to `Localization.Chinese`. Agents can list missing keys by extracting the literals passed to `Localization.T`/`F`, `Row(...)` and `DrawPlacement(...)`; keys reached through variables (title bar buttons, About tabs, disclaimer paragraphs, `LimitLabels`, `AnchorNames`) must be checked by hand.

## Design background

Decisions from the original feasibility study that still constrain changes:

- **Timing is independent of rendering.** Hotkeys go from the hook thread to the scheduler thread, never through the UI loop, so a minimized window or a low frame rate does not delay alerts. Targets: hotkey to scheduled start < 5 ms, alert error < 20 ms (checked by `--scheduler-smoke`), sound onset < 50 ms for prepared clips. Every sound, TTS included, is therefore synthesized and decoded ahead of time into the cache; nothing is synthesized at play time.
- **TTS uses WinRT, not SAPI5.** OneCore voices include the Chinese voices users add under **Settings → Time & language → Speech**, while SAPI5 has fewer; SAPI5 would also need hand-written COM interop (`[GeneratedComInterface]`) under Native AOT. SAPI5 stays the fallback only if the CsWinRT projection stops working under AOT (`--tts-smoke` on the AOT build guards this).
- **Decoders.** Windows has no Vorbis decoder, so Ogg Vorbis uses NVorbis (MIT, managed); Ogg Opus would need another library (for example Concentus) and is rejected. Everything else goes through Media Foundation, so formats missing on N editions without the Media Feature Pack fail with an error rather than a fallback.
- **Hook limits.** The `WH_KEYBOARD_LL` hook only listens: it neither injects nor sends input, which is what the [disclaimer](#disclaimer) states; some anti-cheat software may still object, and that is left to the user. Games that read raw input still deliver keys to a low-level hook, with rare exceptions; verify new games with the manual checks under [Verify and publish](#verify-and-publish).

## Verify and publish

Self-tests and smoke tests are **only for validation during agent work**, guarded by `#if TIPAURA_AGENT_SELF_TEST` and enabled with `-p:EnableAgentSelfTests=true` (default false in every configuration).

```powershell
dotnet run -c Release -p:EnableAgentSelfTests=true -- --self-test        # YAML, packs, Lucide catalog and glyphs, engine, hotkey processor, anchors and window hooks, shader bytecode; no devices
dotnet run -c Release -p:EnableAgentSelfTests=true -- --keybind-smoke    # processor + real low-level hook
dotnet run -c Release -p:EnableAgentSelfTests=true -- --tts-smoke        # lists voices, synthesizes a Chinese phrase
dotnet run -c Release -p:EnableAgentSelfTests=true -- --decode-smoke     # WAV parser, Media Foundation (file and memory), OGG, MP3, M4A; Opus rejected
dotnet run -c Release -p:EnableAgentSelfTests=true -- --audio-smoke      # voice cap and release, max sound length cut-off, at volume 0
dotnet run -c Release -p:EnableAgentSelfTests=true -- --scheduler-smoke  # real-time alert error < 20 ms, repeat drift, reset
dotnet run -c Release -p:EnableAgentSelfTests=true -- --ui-smoke         # main window tabs, both overlays (monochrome in both themes), window hooks, example encounter, Lucide picker, pack load, pack files, save, extraction and Export pack
dotnet run -c Release -p:EnableAgentSelfTests=true -- --capture-smoke    # Discord capture feed, single Present, unchanged screen
dotnet run -c Release -p:EnableAgentSelfTests=true -- --dump-shaders assets/shaders
```

- `--keybind-smoke` sends keypad 5 as non-extended `VK_CLEAR` (and Alt+`VK_CLEAR`) so nothing is typed into the focused window, then captures `VK_CLEAR` once (swallowed) and expects `Numpad5` and no hotkey. The processor part (also in `--self-test`) covers default and custom keys, left/right/either modifiers, an empty reset modifier, `HotkeyBindings.Validate` and the settings JSON round trip.
- `--ui-smoke` opens real windows for about two seconds, installs the global hook, and writes its log, settings and `tipaura.windows.json` (deleted at start) to `%TEMP%\tipaura-ui-smoke`. Its hook step selects a hook that matches no window (both overlays hidden, the current file remembered, the hotkey gate following the hook), then, when listed, a `Title` hook on Explorer's `Program Manager` desktop window (the timeline placed at its anchor), then none, and checks the saved hook file.
- Window hook and anchor checks (`SelfTests/HookSmoke.cs`, part of `--self-test`): placement at anchors and default offsets, clamping, all nine anchor changes keeping the position, following client size changes and round-tripping odd sizes, legacy migration, settings JSON without `Anchor`, hook validation and file round trip, match rules, the own process name, and `HotkeyGate.Allows`.
- `--capture-smoke` (log in `%TEMP%\tipaura-capture-smoke`) places the main window at (0, 0), makes it topmost without activation, and the timeline at (840, 0) from the top-left anchor of the primary work area. It checks each capture frame before Present (timeline size, timeline pixels present; black while the timeline is hidden; still presenting while minimized), reads the window's area back from the screen with `BitBlt` and requires ≥ 95% of the pixels to match the capture-off screen, also after toggling three times. `PrintWindow` cannot be used for this: it shows the main UI even when the composition visual is missing. Without the visual the screen check fails, as it should. Finally it replaces the `Present` (slot 8) and `Present1` (slot 22) entries of the shared DXGI swap chain vtable to record which swap chains present: with About open, both the main window and About present while capture is off (proving the monitor sees other swap chains, composition swap chains included), and with capture on only the main window's HWND swap chain may present, at the timeline size.
- `--self-test` and `--ui-smoke` use `SelfTests/fixtures/example-v1.yaml`, the `data/example.yaml` of commit a80e300 kept verbatim, as the upgrade target: it must load as untagged format 1 equal to the first six timers of the current example, and upgrading a copy must leave a byte-identical `.v1.bak`. Do not edit it; add new format fixtures beside it.
- Pack checks (`SelfTests/PackSmoke.cs`, part of `--self-test`): `SelfTests/fixtures/demo.zip` was written by SharpCompress's `ZipWriter` with Zstandard entries (`index.yaml` with `id: demo`, `sfx/chime.wav`, `sfx/chime.ogg`, `sfx/chime.mp3`, `icons/fire.png` copied from `data/` and `fixtures/`), so the .NET 11 reader is checked against an independent writer. Release Native AOT uses the Windows GUI subsystem. The output is `TipAura.exe`, `cimgui.dll`, `glfw3.dll` and `data/`; keep them together. Expected AOT warnings come only from third-party assemblies: IL2104 for Silk.NET.Input.Common, Silk.NET.Windowing.Common and SharpGen.Runtime, and IL3000/IL3002 for Silk.NET's `DefaultPathResolver`/`DependencyContext`. Silk's platforms are registered explicitly (`AppWindow` static constructor) and the native DLLs sit beside the exe, so those code paths are not needed. SharpCompress produces no AOT warnings. Any warning from TipAura's own code is a regression.

The program icon is `assets/tipaura.ico`, embedded through `ApplicationIcon` as icon group 32512 (the SDK's fixed ID) in both the apphost and the AOT exe. GLFW registers its window class with the stock `IDI_APPLICATION` icon, so `AppWindow` loads that group from the exe module at the system big/small icon sizes and sends `WM_SETICON` to every window it creates (title bar, taskbar, Alt+Tab).

Manual checks the smoke tests cannot replace: hotkeys while the actual game is focused (elevated and not), the hotkey gate with the game and another program in the foreground, overlays following the hooked game window (move, resize, minimize, close), audibility and overlap of TTS and sound files, overlay visibility over the game (borderless windowed; exclusive fullscreen hides overlays), dragging/resizing the unlocked overlays, and whether a Discord stream of the main window shows the timeline with **Discord capture** on.

### Versioning and release workflow

`<Version>` in `TipAura.csproj` is the single version source. Ordinary builds report `<Version>-dev`; only builds with `-p:TipAuraRelease=true` (set by `tools/release.ps1`) report the plain version. `tools/release.ps1` works as in yaaft: from a clean `main`, it publishes Native AOT to `artifacts/release/v<Version>/`, adds `LICENSE.txt` and `licenses/` (`data/` with its `LICENSE.txt` is part of the publish output), zips it to `artifacts/release/tipaura-v<Version>-win-x64.zip`, then creates a squashed commit on the local `public` branch (tree = `main` minus `-Exclude`, default `imgui.ini`) tagged `v<Version>`, using the GitHub noreply address; `main` history and commit messages are never published. A failed build creates no commit or tag. It never pushes and never creates a GitHub release. Then push manually with `git push origin public:main` and `git push origin v<Version>` (never `git push --tags`), and create the GitHub release for the tag with the zip attached. Before pushing, `git log -1 --format='%ae %ce' public` and `git cat-file -p v<Version>` should show only the noreply address. `<RepositoryUrl>` (`https://github.com/xMarch/TipAura`) is shown as a link in About.
